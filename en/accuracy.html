Hardware & Transducer Consistency

Consumer microphones incorporate automatic gain controls and distinct frequency responses. iOS devices maintain strict baseline uniformity, while Android and PC hardware configurations benefit from software calibration offsets.

Best Practices

High-Confidence Documentation Protocol

  • Standardized positioning: Position microphone 1.2–1.5m above floor level, away from reflective surfaces.
  • Contextual documentation: Note window states, ambient room conditions, and active background noise.
  • Calibration alignment: Calibrate using an acoustic reference calibrator or certified meter when possible.
  • Chain-of-custody retention: Preserve raw audio, spectrograms, timestamp logs, and PDF exports together.

What the number means

How a browser meter estimates decibels, and what it cannot certify

SOUNDTEST.PRO reads the microphone through the Web Audio API, applies digital A, C, or Z weighting modeled on IEC 61672-1, and adds a stored device offset. The result is a field estimate for a timeline. It is not a calibrated sound level meter reading.

Signal path

The browser does not receive the raw capsule voltage. The operating system and the browser may still apply gain, automatic gain control, noise suppression, or echo cancellation unless those constraints are turned off. A case, a finger, wind, or a phone lying face-down changes the level before any filter runs. Two phones in the same room can disagree by more than the on-screen tolerance even when both copies of the tool are working as designed.

Where ±1 to 5 dB applies

The device profiles shipped with the product were aligned against a reference sound level meter and a 94 dB acoustic calibrator on common phones. That stated band is for speech-range sound, a clear microphone opening, and a profile that matches the device. Bass through a wall, a siren above the speech band, a covered microphone, or an unknown laptop can fall outside it. A larger gap is a reason to store a calibration offset, not a reason to average two phones and call the result official.

What the SHA-256 line proves

The manifest hash is computed over the exported file bytes. If someone edits the CSV or the PDF, the hash no longer matches. The hash does not prove the microphone was accurate, the GPS fix was the right building, or the note describes the event. A poorly aimed but unedited recording still hashes. File integrity and acoustic truth are different claims, and the export only supports the first.

Phone record and a Class 1 or Class 2 meter

A Class 1 or Class 2 meter under IEC 61672-1 is checked as a whole instrument. At the 1 kHz reference point the acceptance interval is about ±1.1 dB for Class 1 and ±1.4 dB for Class 2, and it widens across frequency, direction, and temperature. Copying the A-weighting curve in software does not put a phone into either class. Use the phone record to show when, where, and roughly how loud an event was, with audio and notes. Use a certified meter, run by the method the rule names, when a fine, a lease penalty, or an enforcement file depends on the number itself.

Keep one session comparable with the next

  • Same phone, same case, same weighting, and the same Fast or Slow response.
  • Microphone about 1.2–1.5 m off the floor, not in a pocket and not against a wall.
  • Write down windows, other sources, and the distance if you know it. A peak with no duration is hard to compare with LAeq or with an 8-hour dose.
  • If the number will be shown next to a limit, set the offset from a calibrator or from a meter you trust, and keep that offset inside the export.
  • Save the audio, the CSV, the PDF, and the manifest together. The hash only covers the files you actually hash.

Read the limit figures on the standards page before comparing a take with WHO, OSHA, or a local rule, and keep the raw files with the sample dossier layout. Open the recorder when the notes are ready. The recorder does not decide compliance.
